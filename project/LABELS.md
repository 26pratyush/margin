# GitHub label definitions

Create these labels in the repository. Keep the palette restrained and use labels for filtering, not decoration.

| Label | Meaning |
| --- | --- |
| `epic` | Large outcome containing multiple issues |
| `feature` | User-facing capability |
| `task` | Focused implementation or documentation unit |
| `bug` | Incorrect or broken behavior |
| `chore` | Maintenance or tooling work |
| `documentation` | Docs, Wiki, or project management |
| `area:app` | Local finance application |
| `area:design` | UX, UI, or visual system |
| `area:site` | Static product/demo website |
| `area:docs` | Documentation and project context |
| `area:testing` | Tests and quality checks |
| `area:devops` | Repository, CI, or deployment |
| `priority:p0` | Blocks the current release or risks data safety |
| `priority:p1` | Important for the current milestone |
| `priority:p2` | Valuable but not blocking |
| `priority:p3` | Optional or exploratory |
| `status:blocked` | Cannot proceed without a dependency or decision |

# MARGIN-001 — Establish project baseline and GitHub workflow

## Goal

Make the repository understandable and usable as the source of truth for future work.

## Scope

- Review README, project context, architecture boundary, and Wiki-ready pages.
- Create the GitHub Project, milestones, labels, and initial views.
- Add issue and Pull Request templates.
- Protect `main` when the repository is ready for regular PRs.

## Acceptance criteria

- A new contributor can find the product boundary and first epic in under five minutes.
- GitHub issues can be created consistently for epics, features, tasks, bugs, and docs.
- The Project has Roadmap, Current Wave, Backlog, Bugs, and Product Website views.
- The first epic and all task briefs are linked from the repository.

## Out of scope

Choosing the application framework or implementing product code.
